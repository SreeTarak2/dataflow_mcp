FLAGS RULES (STRICT)
==================================================
flags is an array. Only use values from this list:

"women"      → hackathon is EXCLUSIVELY for women.
               Do NOT set if open to other genders.

"hero"       → hackathon is visually compelling and suitable
               for the hero slider. Set when:
               - Prize pool totalUSD >= $10,000 AND has a clear
                 primary image
               - OR organized by a major platform/company
                 (Google, Microsoft, Devfolio, MLH, Unstop,
                 HackerEarth, AWS, Meta, NASA, UN)
               - OR has strong visual branding + notable prestige

"broken-link"→ official link is confirmed unreachable.

"all"  → hackathon is explicitly open to participants of all
         genders (men and women). Set when eligibility clearly
         states no gender restriction.

         Appears on BOTH the main Contests page AND the For Her
         page. Do NOT set when gender info is absent (use []).

- Default: []
- NEVER speculate
- "hero" and "women" can coexist in the same entry
- "all" and "women" must NOT coexist — they are opposites

==================================================
PRIZE RULES (EVIDENCE-BASED)
==================================================
originalAmount: the raw stated number (in stated currency)
totalUSD: USD equivalent (convert if currency is known; else = originalAmount)
currency: ISO code — default "USD"

Classification:
1. Explicit prize amount          → isMonetary = true, fill amounts
2. Prize pool mentioned, no amount→ isMonetary = true, amounts = 0
3. Only swag / recognition        → isMonetary = false, amounts = 0
4. No prize info at all           → isMonetary = null, amounts = 0

For Indian Rupee (INR): divide by 84 to get approximate USD equivalent.
For Euros (EUR): multiply by 1.08.

NEVER infer money. NEVER round up aggressively.

==================================================
TIMEZONE RULES
==================================================
1. If organizer city or country is explicit → map to correct timezone
2. If unclear or international → "UTC"
3. If date exists but no timezone → assume 23:59 UTC, set "UTC"

Common mappings:
- India → "Asia/Kolkata"
- USA East → "America/New_York"
- USA West → "America/Los_Angeles"
- UK → "Europe/London"
- Germany / CET → "Europe/Berlin"

NEVER invent timezones.

==================================================
JUDGING CRITERIA RULES
==================================================
judgingCriteria is an array of scoring dimensions.

- Extract ONLY from explicitly listed judging criteria on the page.
- Each entry: { "name": "<criterion>", "description": "<explanation>", "weight": <number or null> }
- "name": short label, e.g. "Innovation", "Technical Execution", "Impact"
- "description": 1 sentence explaining what judges look for.
- "weight": percentage as integer (e.g. 30) if explicitly stated; else null.
- Maximum 6 criteria. If none listed → use [] (empty array).
- NEVER invent criteria not stated on the page.

==================================================
SUBMISSION REQUIREMENTS RULES
==================================================
submissionRequirements is a plain string array.

- Extract ONLY explicitly listed submission items from the page.
- Each entry is a single plain string describing one required item.

==================================================
HACKATHON-SPECIFIC NOTES
==================================================
1. Many hackathons have a REGISTRATION DEADLINE separate from the
   SUBMISSION DEADLINE. Always use the submission deadline for
   timeline.submissionDeadlineUTC. Store the registration close date
   in timeline.registrationEnd.

2. Prize pools for hackathons often include "total prizes" (all tracks
   combined). Use the TOTAL prize pool as originalAmount.

3. Team size is very common in hackathons. Extract it carefully:
   - "Solo or teams up to 5" → min: 1, max: 5
   - "Teams of 2–4" → min: 2, max: 4
   - "Individual only" → min: 1, max: 1

4. Devpost hackathons: the registration count / submission count
   is NOT the prize amount. Do not confuse these numbers.

5. MLH hackathons: always check for MLH Code of Conduct compliance
   requirement — this does NOT affect eligibility for our schema.

6. Many hackathons have a "Themes" section. Map these to
   filterKeys.themes in kebab-case.
